# Architecture

## Records and SDK ownership

An existing task owns the registered string field `http_state`. Its version-1 envelope contains a monotonic revision, immutable probes, replaceable explicit contracts, append-only observations and per-operation send plans. Native SDK comments record each transition. Declarations also add their secret-free URL templates as native SDK source links in the same conditional mutation; existing link notes survive. Links are references and execute no requests. Task identity, settings/author selection, schema registration, complete field reads, item locks and conditional mutation transactions use the public pm SDK. No package-owned generic store or direct tracker-file writer exists. Native task links and context collections remain available through pm; declarations and evidence travel with the task field and its audited history.

`Store.change` takes an SDK lease for package state, reads the current native target, compares any expected revision, and writes only `http_state` plus an attributable comment through `commitItemMutations`. The transaction checks the full prior envelope under the native item lock; initial admission checks the task's native `updated_at`. Other native fields survive updates. Package revisions only increase. A no-op is returned only after re-reading the current target. Native competing edits cause a typed conflict, never blind replay. The canonical task identity binds send-operation locks.

Readers request full native items with explicit unbounded output controls. This preserves saved HTTP state even if its schema-registry entry was removed. Task and revision validation precede schema writes. Public list/observation/comparison/missing APIs return source-completeness receipts. A bounded packet distinguishes a complete source read from omitted presentation rows.

## Send journal and recovery

Each explicit send uses a stable operation ID. Its declaration digest includes method, URL template, environment reference names, body reference, boundary, ceilings, selected headers and any reviewed capability. The journal stages are `planned`, `sending`, `received`, `recorded`, or `cancelled`. A per-operation SDK lease prevents two callers from executing the same send concurrently. Different operations can send concurrently; every recording step merges against the freshly read task revision.

The plan is durable before any request effect. Marking `sending` is durable before opening the request. The complete secret-free response is journaled before observation admission. The final atomic state mutation appends one observation, marks the plan recorded and removes the redundant journal result. Rerunning a recorded operation returns its current stored observation. A received operation completes recording. A sending operation interrupted before its result became durable converges to an explicit uncertain observation, with no resend. Cancelled/refused operations retain their audit record and produce no partial observation. A new request always requires a new explicit operation identity. No methods receive automatic retries.

Recovery never trusts an earlier plan over current sources: the probe digest and current target revision are revalidated on every journal step, including unchanged paths. Editing a declaration/review after planning refuses with a conflict. A stable operation ID cannot be reassigned to a different declaration. Eight public boundaries (`validated`, `plan-ready`, `planned`, `sending`, `received`, `record-ready`, `recorded`, `complete`) drive independent competing-write and crash schedules. The tests also inject a real native SDK write after transaction preparation to prove the conditional mutation refuses a changed target.

The SDK's own one-item transaction is the atomic domain-write boundary; its journals and locks are runtime state. Historical native audit entries are never removed or rewritten. A crash while a possible request is in flight can lose the response, but cannot justify guessing that the request failed or resending an uncertain mutation.

## Redaction and structural admission

The package does not attempt to classify arbitrary response prose as safe. It discards all scalar body values and hashes every JSON property name. Arrays retain unique structural item shapes. Structural capture is bounded by breadth, depth and node ceilings and reports omissions. Contracts compile the same property-name hash representation, allowing required-field/type comparisons without retaining names or response values. SHA-256 response digests identify complete bytes or explicitly labeled captured prefixes; digests are not raw response archives.

Request header values are fixed safe MIME/User-Agent literals or `@ENV_NAME`. Query values, opaque path identifiers and request bodies are environment references. References resolve only at send time; ephemeral values never enter SDK mutation arguments, journals, history, output or diagnostics. Body references may contain arbitrary bytes represented as a process string, bounded to 1 MiB; path references must resolve to one safe identifier segment. No credential file is read and no environment is enumerated. Dry-run uses the same request planner with resolution disabled.

Header capture emits only selected names within the count ceiling. Content-Type is normalized to a fixed MIME set; Content-Length/Retry-After accept bounded canonical integers; Cache-Control accepts a narrow fixed grammar. All other values are redacted, including Set-Cookie, authorization-like and opaque token-shaped headers. Explicit credential echoes and controls are redacted before normalization. The receipt counts redacted captured headers and headers omitted beyond the ceiling; unselected headers also retain no value. Raw response strings never enter diagnostics. Renderers recursively escape controls, ANSI bytes, backticks and instruction delimiters, including object keys.

This is data minimization, not a promise that a digest cannot be correlated with a guessed value. Operators must put credentials in references and keep review reasons and static declarations free of secrets. No body excerpt facility exists.

## Destination and transport rules

The boundary fixes HTTP(S) scheme, canonical host, effective port and a static path-prefix segment. Every request and redirect checks the same boundary function before DNS or socket effects. `/api` includes `/api/child`, never `/apievil`. URL parsing rejects userinfo, fragments, percent-encoded/ambiguous paths and backslashes; canonical dot-segment normalization happens before confinement. A refusing redirect receipt identifies the hop number and target digest, never a raw secret-bearing Location. Mutating redirects refuse instead of changing method or resending a body.

Each hop resolves DNS, validates every answer and pins an admitted address into the actual request lookup. Public hostnames cannot authorize private results. A boundary explicitly naming a literal private address or localhost permits that declared private destination. Origin confinement prevents credential forwarding to another origin. IPv4 normalization and conservative IPv6/reserved-range classification close alternate loopback representations. HTTPS certificate verification stays enabled. No proxy environment, cookie jar, browser state or implicit authentication is used.

One AbortController bounds the full request lifecycle, including DNS waits, all redirect bodies, connect/TLS and final response. A caller AbortSignal/SIGINT produces a typed cancellation and no partial observation. Transport failure/timeout produces an uncertain historical outcome with a zero-retry receipt. Byte truncation closes the stream promptly and labels digest scope. Header parsing has a 16 KiB allocation ceiling; count processing is separately capped with an exact omitted-header count for parsed responses. Header-parser overflow becomes uncertainty rather than a fabricated complete response. No decompression is performed.

DNS/connect/TLS/first-byte timings are included when available, measured cumulatively from request start in milliseconds; total time is numeric when measured and null when interrupted-send recovery cannot measure it. Missing phases are absent rather than invented zeros. Observation timestamps are recorded when the result is captured; recovered interrupted-send uncertainty is timestamped at recovery and explicitly names its uncertainty. Timings and status are historical evidence.

## Comparison and difference algorithm

Contracts define status alternatives, required selected headers (redacted values still prove presence), optional structural JSON requirements and a total latency ceiling. Properties are required recursively, extra properties are accepted, and all array items must match. The supported shape grammar excludes arbitrary JSON Schema expressions or executable validation. A changed probe digest, missing contract or uncertain outcome yields `unknown`. Incomplete captures cannot satisfy a contract, but a known bad status, excessive latency or fully captured mismatch still proves a violation. Complete response violations identify status, header, JSON shape and latency reasons. None of these verdicts imply present availability.

For each probe, observations sort by timestamp and stable ID. Find the first contract violation and its preceding last satisfying observation. If no violation exists, compare the latest pair; absent predecessors remain explicit null identities. Compare status, outcome, body digest/length, total timing, retry receipts, selected headers and each structural shape field. Include source observation IDs/timestamps, verdict reasons and exact per-field differences. Unknown evidence never becomes last-good evidence. Independent missing rows identify each absent observation, contract or complete capture.

The packet prioritizes missing-evidence rows, then deterministic per-probe difference rows. It estimates the larger actual JSON/TOON wire size, including newline and the self-inclusive estimate/receipt, as bytes divided by four rounded up. Rows that do not fit are omitted; receipts state exact omitted/returned counts and commands to restore the full diff or missing-evidence list. The estimate is conservative across these two serializations, not model-token exact. Source reads are complete even when packet rows are omitted.

## Limits and backend boundary

Defaults and hard ceilings are documented in the README and validated before effects. Task envelopes cap operations and observations at 128, probes at 32 and serialized state at 1 MiB. Shape work, contract-file size, request/response bytes, header count/parser bytes, redirects, wall time and packet cost all have independent bounds. Synthetic fixtures contain no hosted user data. The ten-request measurement deletes its scratch tracker and stores only aggregate numbers and public endpoint descriptions.

Everything works without git. Injected native clients support other backends for reads. Current public `CommitItemMutationsOptions` and `CommitWorkspaceTransactionOptions` both require `pmRoot: string`; `ExtensionCommandSdk` does not expose a backend-owned conditional writer. [Open upstream #1399](https://github.com/unbraind/pm-cli/issues/1399) owns that capability. The package refuses remote writes and sends before schema, journal or network effects instead of claiming remote mutation conformance.
